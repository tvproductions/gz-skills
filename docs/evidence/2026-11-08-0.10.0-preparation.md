## Draft release notes and migration

Bundle 0.10.0 removes the `gzkit` vendoring surface. New attempts to use
`gz-skills install --surface gzkit` fail argument validation before writing.
Supported named surfaces remain `agents`, `claude`, `codex` and `github`; an
explicit target directory remains available for project-owned use. The setup
guard continues to reject mixing the ecosystems in a `.gzkit/` project.

Existing files, locks and installed plugins are not moved or deleted. Consumers
with an old gzkit-targeted installation must explicitly reconcile that copy and
choose one ecosystem before installing this catalog in a supported agent
scope. Do not install a second copy into the same discovery scope. Historical
extraction provenance remains history, not an interoperability promise.

The four skill corrections above preserve invocation, mutation authority,
freshness-only behavior, verification and failure boundaries. The
[initial dependency-update review](../review/gzs-update-dependencies-2026-11-08.md)
is complete: keep candidate 0.4.1, with its initial finding closed by static
inspection. It does not grant stable acceptance. Repository release-planning
clarifications are included as documentation, with no new consumer baseline.
